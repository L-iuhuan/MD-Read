## 1. 定位与目标

个人自用 Windows 桌面 Markdown **阅读器**：阅读为主 + 轻量编辑 + 导出 PDF。

**立足点（差异化）**：竞品没有一个同时占住「浏览器级排版质量 + 中文优先排版」——
- Ferrite（OlaProeis，Rust + egui，1.7k★）：自绘文本无 CSS 排版能力，中文两端对齐/混排间距/标点挤压全做不了，"糊且丑"的根因
- MarkView（SureshAmal，Tauri + Next.js/React/Tailwind）：有 WebView2 但 react-markdown 慢、无中文排版投入、通用 Tailwind 外观
- MD Reader（Neilooo，Tauri，4.2MB msi）：方向对（小体积+文件关联+Ctrl+/），中文排版与导出未做到位

墨读 = Tauri 2 + WebView2（浏览器排版底子）+ 手写 CSS（中文排版投入）+ 小包（目标 ≤8MB msi）。

**用户场景**：财务/数据从业者，双机（公司内网机 + 家机 外网），读技术文档、AI 输出、自产分析报告 .md；随手改错字；需要时导出 PDF 交付。

## 2. 需求规格

### 2.2 非功能需求

- 包体积目标 **≤ 8 MB msi**（KaTeX 字体 ~1MB 本地化；Mermaid ~1.5MB 懒加载；中文字体不打包走系统栈）
- 性能底线：1 MB / ~5000 行文档打开 <1s、滚动不卡；**不做虚拟滚动**
- 双机可构建；代码 git 同步（`pull --rebase` 纪律）

### 2.3 明确不做（YAGNI）

Word 导出（OMML 全链）✂️；jsPDF/html2canvas 光栅化 ✂️；多光标/补全/Vim 模式 ✂️；插件系统 ✂️；云同步 ✂️；文件夹工作区与跨文件搜索（**二期另立计划**）✂️。

## 3. GUI 设计

### 3.1 线框

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 标签栏   [季度分析.md ●] [会议纪要.md] [+]                          │
├──────────────────────────────────────────────────────────────────────┤
│ ② 工具条   [☰大纲]  ← 季度分析.md →   [Aa] [◐主题] [✎编辑] [⇩PDF] [⚙] │
├────────────┬─────────────────────────────────────────────────────────┤
│ ③ 大纲侧栏  │ ④ 正文区（唯一主区，限宽 ~46em 居中）                     │
│  (可折叠)   │    标题层级靠字号/重量/间距拉开，不靠边框堆砌              │
│ ▾ 1 概述    │    正文两端对齐、行高 1.8、标点挤压                       │
│ ▸ 2 数据    │    公式（矢量）/ 代码块（语言标签）/ 表格 / Mermaid        │
│ ─────────  │                                                         │
│ 进度 62%   │                                                         │
├────────────┴─────────────────────────────────────────────────────────┤
│ ⑤ 状态栏   行 128/640 · 3,241 字 · UTF-8 · 阅读 62%                   │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.2 交互

- `Ctrl+E` 阅读↔编辑整态切换（编辑态同一位置换 CM6，行宽一致）
- `Ctrl+F` 查找条；`Ctrl+H` 替换（编辑态）；`Ctrl+P` 导出打印；`Ctrl+S` 保存
- 阅读态沉浸滚动时工具条自动淡出（**动效 ≤250ms**，用户动效上限）
- focus-visible 可见焦点态；内容加载用骨架屏（补位底线两条）

### 3.3 主题与配色协议（强制，按《设计参考-token与配色.md》）

- 色值只从 **Radix Colors 阶数**取（UI 单体系），结构刻度（间距/字号/圆角/阴影）从 **Open Props** 抄，不自造 hex
- 亮暗双套成对设计、同步验收；正文对比度 ≥4.5:1
- **M1 排版 demo 评审轮**：真场景页（标题/正文/表格/代码/公式/Mermaid）出 2-3 个组装方案，用户否决定稿，批准后才进工程——先于一切 GUI 代码
- 语义色：红=错误 绿=通过 黄=警告 蓝=信息

## 4. 架构决策（D1–D5，带证据）

| 决策 | 裁决 | 依据 |
|---|---|---|
| D1 编辑器底座 | **双引擎切换**：阅读态=markdown-it 静态 HTML；编辑态=CodeMirror 6。`token.map`→渲染块 `data-line`→切换按可见块行号映射保位 | contenteditable 的中文 IME 风险不可控；CM6 Live Preview（Obsidian 式）工作量翻倍，列三期可选，双引擎架构不堵死 |
| D2 PDF 导出 | M1：`window.print()` + `@media print`（零 Rust、矢量质量）；M5：Rust `with_webview` → `cast::<ICoreWebView2_7>()` → **`PrintToPdf` 静默直出**（微软官方 API；StackOverflow 有 Tauri 完整 POC；wry 无原生打印 API 已确认）。**页码走 PrintSettings header/footer，禁碰 `@page` margin-box** | Print Studio 翻车三根因全绕开：margin-box Chromium 不支持 ✂️、光栅化变糊 ✂️、CDN 字体丢失 ✂️（Tauri 本地资源） |
| D3 中文排版 | 生效：`justify`、`text-spacing-trim`（Chrome 123–153 ✓，caniuse 实证）、行高/限宽/字体栈；**不生效：`text-autospace`（Chrome ≤153 全红，caniuse 实证）**→ pangu 式 JS 插空格 + `CSS.supports()` 运行时检测降级 | caniuse + Chrome 官方 i18n 博客，2026-09-21 核实 |
| D4 性能 | 不做虚拟滚动；Mermaid/KaTeX 懒加载（首块出现才加载）；大文档 requestIdleCallback 分块渲染 | 用户未勾大文件痛点，守 1MB 底线 |
| D5 Print Studio 资产 | 搬：markdown-it 配置/fence 规则（语言标签+保证 code 包裹）/`@media print` 主体规则（print-color-adjust、box-decoration-break、page-break-inside:avoid）/KaTeX 本地化思路/refreshMermaidTheme；**重取**：全部色值（Radix，2026-09-18 用户纠偏禁止沿用旧表）；删：光栅化链（rasterizeKatexForExport/canvasToPDF/nodeToPng/svgMarkupToPng）、OMML 链、CDN+cdnFail 层、3164 行巨石结构 | 逐函数盘点 2026-09-21 |

## 6. 质量门禁

- `tsc --strict`（禁 any）+ eslint + vitest，一条命令 `pnpm check` 全绿才许提交
- 渲染管线 **golden-HTML 快照对拍**（固定语料，防回归）
- 排版走**截图验收轮**：E2E 截图→发现问题→修复→同名截图复核
- Rust 侧 `cargo test`
- TS 版铁律（照搬 Python 铁律）：文件 ≤250 行纯代码、函数 ≤50 行、禁宽 catch/空 catch、全类型注解
- 错误信息中文、面向使用者
