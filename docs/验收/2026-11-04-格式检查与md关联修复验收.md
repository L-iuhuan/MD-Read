## 二、.md 默认关联自愈（0.2.16）

### 根因（本机注册表取证）

- `UserChoice(.md) → MoDu.md` **仍在**（你的默认选择从未丢失）；
- 但 `HKCU\Software\Classes\MoDu.md\shell\open\command` 仍指向**已卸载的旧 MSI 位置** `C:\Program Files\MoDu\modu.exe`（该文件已不存在）；
- 双击 .md 沿链走到死路径 ⇒ 表现为「默认打开丢失 / 重装也要重新指定」。
- 该键为应用侧手写，安装器从不更新；旧自愈只刷图标不修命令。

### 修复方式

启动时后台自愈：ProgID 键已存在（注册过）且 open command 不指向当前安装（死链或旧路径）时，静默重写 command / 图标 / OpenWithProgids 三件套到当前 exe；从未注册过的机器零副作用；UserChoice 永不触碰。dev/测试构建（exe 在 `target\` 下）跳过，不污染开发机注册表。

### 验收步骤

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 安装 `MoDu_0.2.16_x64-setup.exe`（覆盖安装即可） | 安装完成 |
| 2 | 从开始菜单/桌面启动墨读一次（让自愈跑完，静默无感） | 正常打开 |
| 3 | 资源管理器双击任意 .md 文件 | **直接用墨读打开，不弹「选择打开方式」** |
| 4 | （可选）`reg query "HKCU\Software\Classes\MoDu.md\shell\open\command" /ve` | 值指向 `C:\Users\<你>\AppData\Local\MoDu\modu.exe` |
| 5 | （回归）墨读内打开/保存/导出 PDF、阅读态大纲跳转 | 功能无损 |

> 若步骤 3 仍弹选择框：说明系统已在你之前测试期间重置过 UserChoice——在「设置 → 默认应用」里对 .md 点选一次墨读即可（一次性动作，之后重装不再需要）。
