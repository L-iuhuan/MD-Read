## 1. D1/D2/D4：`$$` 数学管线（Lead）

### D1 多行 `$$` 整块不渲染
- 最小复现：`renderDocument("$$\nE = mc^2\n$$\n")` → 修前 `<p>$$<br>E = mc^2<br>$$</p>`，**零 `.katex`**。
- 因果链：`pipeline.ts` 快路径 `needGuard = src.includes("\\(") || src.includes("\\[")` 把「只含 `$$`」的文档判为无公式 → 跳过 `extractMath` → `breaks:true` 把换行渲染成 `<br>` → **KaTeX auto-render 按单个文本节点匹配定界符**，开/闭 `$$` 被劈进两个文本节点 ⇒ 配不上。
- 同类旁证：同一条件下 `$$a *b* c$$` 的块体被 emphasis 拆散，也漏渲。
- 修复：`needGuard` 计入 `$$`。原注释「`$$` 无反斜杠不需保护」是错的。

### D2 跨块误配对（本次最严重）
- 最小复现 A（两个 bash 围栏各含 `echo $$` + 正文另有 `\(x\)`）：
  修前第一个 `<pre>` 内容 = `"echo $$\n```\n\n中间段落甲\n\n```bash\necho $$\n"` —— **中间段落与第二个围栏线被吞进第一个代码块**。
- 最小复现 B（正文两个裸 `$$` + 另有 `\(x\)`）：`价格 $$ 折扣甲` / `# 标题甲` / `再 $$ 一次`
  → **`# 标题甲` 不再是标题**，整段退化成 `<p>` 里的字面文本（含 CJK 时被 `.math-fallback` 收走）。
- 根因：`extractMath` 在**原始源文**上按字符序列配对，不区分正文/代码；配对成功后那段原文在 render 之后被**原样塞回 HTML**，其间的 markdown 再没有机会被解析。
- 修复：新增 `codeIntervals()`（围栏代码块 + 行内码区间内定界符**一律不参与配对**）+ 多行 `$$` 必须**两端行级独占**（剥掉缩进/引用栈/列表标记后正好是 `$$`，其后只有空白）。
- 性能：1.85MB / 14317 片段实测 `extractMath` 15–30ms（P1-5 预算 120–150ms 内）；`codeIntervals` 用粘性正则 + 游标遍历（不逐行 slice）。

### D4 宽松多行 `$$`
- `$$E\n= mc^2$$`、`$$\nE = mc^2$$`、`$$E = mc^2\n$$` 三种「定界符与内容同行」写法修前整块字面。
- **没有**用「放宽 D2 配对规则」的方式修（那会重新打开跨块吞文档）；改在 `math.ts` 加 `joinDollarAcrossBreaks()`：只在**同一个块元素内部**，把落在成对 `$$` 区间内的直接子 `<br>` 换成 `\n` 再 `normalize()`。作用域被限定在一个块内 ⇒ 结构上不可能吞掉别的块。
- 实测：三种形态都出 `.katex-display`；`$$中文\n公式$$` 走 `.math-fallback--display`；跨度外硬换行 `<br>` 计数不受影响。

### D5/D6 mathprotect 的「安全网」自身的两个洞（审查员发现、Lead 修）
- D5：`scanInlineCode` 在整段非围栏区配对反引号，**不守「行内码不能跨空行」** ⇒ 两处游离单反引号被当成一个跨块代码区间，区间里的 `\(x^2\)` 被跳过 ⇒ 退化成普通括号 `(x^2)`。
  修：闭合跑必须落在 `paragraphEnd()`（空行前）之内；合法跨行行内码（段内单换行）不受影响。
- D6：`extractMath` 遇到最早一个未闭合 `\(` 就 `break` ⇒ 其后独立成对的 `\[e+f\]` 全部失保护。
  修：改为 `continue`（只跳过它自己）。

## 2. D7：`www.` 自动成链（Lead）

- 注释原文：「scheme/www 前缀仍自动成链」。实测 `www.example.com` → **字面文本**。
- 根因：linkify-it 的 `www.` 匹配**就在 fuzzyLink 路径里**（`re.host_fuzzy_test` = `localhost|www\.|\.\d{1,3}\.|\....TLD`）；2026-10-01 关掉 `fuzzyLink` 时把 `www.` 一起关掉了。
- 修：新增 `installWwwAutolink`（core rule，挂在 `linkify` 之后），复用 linkify-it 自身的 TLD 表与校验（构造器从现成实例取，**不引新依赖**），但**只接受 `www.` 前缀** —— 裸域名继续不成链（`笔记.md` → punycode 的实害不复活）。
- 实测：`www.example.com`（含路径/查询/锚点）成链且 href 补 `http://`；`笔记.md` / `a.example.com` / `方案.docx` / `www.foo` / `www.` / 邮箱 / 行内码 / 围栏 / 链接标签内一律不成链；CJK 标点紧邻仍成链；大写 `WWW.` 不成链（与 cmark-gfm 的 www autolink 一致）。

## 2.5 D3：未引用的脚注定义不再整行消失（Lead）

- 实害：写了 `[^a]: 定义` 但全文没有 `[^a]` 引用 ⇒ **整行消失**。
  机制：markdown-it-footnote 的 `footnote_tail` 会把**所有** `[^a]: …` 区块的 token 从正文 token 流里摘走，
  只有被引用过的才重新拼到文末脚注区 —— 没引用的那份直接丢弃（GFM 同行为）。
- 修法：在 `footnote_tail` **之前**插一条 core rule（`markdown.ts installFootnoteKeepRule`）：
  此时 inline 解析已完成，`env.footnotes.refs[label] === -1` 就是「定义了但没被引用」；
  把这类定义的 `footnote_reference_open/close` **标记拆掉**、内容块留在原 token 流里
  ⇒ 按作者写的位置渲染成普通块。被引用的一律不动，照旧进文末脚注区。
- 口径：与其它块级标记一致（`#`/`-`/`>` 也不显示），保留的是**内容与位置**。
- 实测：未引用定义按原位成段且 `data-line` 正确（第 3 行就是 3）；多行体（缩进续行）两行都在；
  定义内含列表照样渲染；混合形态下引用的进脚注区、未引用的留原位（各一份，不重复）。
- 锚：`tests/footnote-keep.spec.ts`（9 项，含「定义在引用之前」这条顺序锚）。
- 顺带修掉三个低危项（render.md U4/U5/U6，锚 `tests/render-audit-lowfix.spec.ts` 9 项）：
  · U4 链接目标里的裸 TAB 也编码（上游会把裸 TAB 静默吞掉，`[x](a<TAB>b.md)` 实际指向 `ab.md`）；
  · U5 ≥16 位**纯数字**不再包 `.tok-break`（财务场景里多半是账号/卡号，断在中间会被读成两段）；
  · U6 pangu 不再进 `.math-fallback`（降级公式体与 KaTeX 渲染的公式都不该有中西文插空）。

## 4. 「需要空行才能完整渲染」——逐条判定

**判定：除 D1/D4 外全部是 CommonMark 规范行为。** 下表是实测（探针 `.verify/audit/cases*/`）：

| 写法 | 实测 | 判定 |
|---|---|---|
| `段落` + `\| 表 \|` 无空行 | 成表 | 规范（不需要空行） |
| `段落` + `- 列表` 无空行 | 成列表 | 规范 |
| `段落` + `1. 列表` 无空行 | 成列表 | 规范 |
| `段落` + `2. 列表` 无空行 | **不成列表** | 规范：有序列表只有 `1.` 能打断段落 |
| `段落` + `> 引用` 无空行 | 成引用 | 规范 |
| `段落` + `# 标题` 无空行 | 成标题 | 规范 |
| `段落` + 围栏 / mermaid 无空行 | 成块 | 规范 |
| `段落` + 4 空格缩进 | **并入段落** | 规范：缩进代码块不能打断段落 |
| `段落` + `---` | **变 Setext 二级标题** | 规范：Setext 优先于 thematic break（要横线用 `***`/`___`） |
| `- 项` + 普通文字（无空行） | 文字**并入最后一个列表项** | 规范：懒延续 |
| `> 引用` + 普通文字（无空行） | 文字并入引用 | 规范：懒延续 |
| `- 项` + 表格（无空行无缩进） | 表格行成为列表项里的**字面文本** | 规范（缩进 2 格或加空行即成表） |
| `标题` + `---` | 变 Setext 标题 | 规范 |
| 未引用脚注定义 `[^a]: …` | **整行消失** | GFM/markdown-it-footnote 行为 ⇒ 见 D3 |
| 定义列表 `术语` + `: 定义` | 字面 | 不支持（规格 F2 未含） |
| `==高亮==` / `[[双链]]` / `H~2~O` | 字面 | 不支持（同上） |
| 内联 HTML（`<div>`/`<br>`/`<img onerror>`） | 转义成文本 | D6 安全红线，设计如此 |
| 表格单元格里的 `<br>` | 字面 `<br>` | html:false 的必然后果（GFM 靠原生 HTML 支持，本应用不支持） |

### 7b 裸域名自动成链：为什么「安全地开」很难，以及真要开该怎么做

**结论：建议保持现状（裸域名不成链），只保留 `www.` 与 `scheme://`。**

难点：linkify-it 判定裸域名的**唯一**依据是「最后一段命中它内置的 TLD 表」，
而一批常见**文件扩展名本身就是真实 TLD**：

| 扩展名 | 同时是 | 后果 |
|---|---|---|
| `.md` | 摩尔多瓦 | `笔记.md` / `README.md` → 成链 → 点击跳浏览器（你 2026-10-01 报的实害） |
| `.sh` | 圣赫勒拿 | `build.sh` → 成链 |
| `.py` | 巴拉圭 | `main.py` → 成链 |
| `.rs` | 塞尔维亚 | `lib.rs` → 成链 |
| `.pl` | 波兰 | `script.pl` → 成链 |
| `.so` | 索马里 | `libfoo.so` → 成链 |
| `.cc` | 科科斯群岛 | `a.cc` → 成链 |
| `.zip` | 通用 TLD | `archive.zip` → 成链 |

⇒ **不存在「只看字符串」就能把 `notes.md` 与 `example.com` 分开的规则**：两者形状完全相同，
差别只是「人知道哪个是文件名」。其余信号（后面跟不跟中文、前面是不是「见/打开」）都是语义级的，做不到。
（推断，未联网复核：GFM 的裸域名规则只要求「ASCII 标签 + 纯字母 TLD」，`.md`/`.sh`/`.py` 都满足
⇒ **即便做到与 GFM 完全一致，也仍会把 `notes.md` 当域名**。）

三条路：

1. **保持关闭（推荐，现状）**：`www.example.com` / `https://…` 成链，裸 `example.com` 不成链。
   代价：裸域名要手打 `www.` 或 `https://`（或写成 `[example.com](https://example.com)`）。
   收益：`README.md`、`build.sh`、`main.py` **永远不会**变成外链。
2. **开 + TLD 白名单**：只对「确实当网站用」的 TLD 白名单（`com cn org net edu gov io dev app me cc tv xyz top info …`）
   做裸域名成链，把 `md sh rs py pl so cc cm gs la zip ps` 这类文件扩展名高频项排除。
   能跑，但**要维护一张表，且白名单内仍会误伤**（`a.io`、`model.ai`、`data.dev`）。
3. **开 + 形状启发式**：要求带 `/`、`?`、`#`，或域名段数 ≥3（`docs.python.org` 成链、`notes.md` 不成链）。
   规则越细解释成本越高，误伤只是换个类别（`lib.rs` 仍会中）。

要 2 的话我可以实现成「ASCII 域名 + TLD 白名单 + 排除文件后缀」，并配正反锚
（把你踩过的 `笔记.md` 钉成永久回归锚）。
