## 2. ⭐ 定性：写成【特性】而不是【上限】
```
≤2007 条目：中位 冷 12.8ms / 热 11.7ms、p95 12.8–13.3ms ⇒ **远在一帧（16.7ms）内** ✓、**零长任务** ✓
按 6.4µs/条 外推（**推断** ✗）：≈ **2600 条目 ≈ 一帧**
5007 条目：32.5ms ⇒ **已超一帧**，但**依然零长任务**（>50ms 计数器未触发 ✓）⇒ **不阻塞** ✓
⇒ 实测 ≤2007 达标 ✓；2007–5007 **未按验收口径测** ✗；5007 已超一帧但**不阻塞** ✓
```
**裁定（Lead 2026-09-25）：不设上限、不做缓解** ✓ —— 理由（实测 ✓）：已批准范围内不到一帧、零长任务、斜率线性；
真实文件夹即使超过 2600 个文件，代价也只有 **~32ms** ⇒ **不值得引入"显示更多"/硬上限这类无据复杂度** ✗。

`limit` 现状（读 Rust 原文 ✓）：
```
Rust `list_dir_at(trust, raw, limit: Option<usize>)` ⇒ **单遍 read_dir、收满 limit 即停止收集** ✓（安全网 API 在 ✓）
前端 `invoke<DirListing>("list_dir", { path })` ⇒ **不传 limit** ✗ ⇒ **current limit = None ⇒ 实际无上限** ✓
```

## 4. 本轮教训（都进 `AGENTS.md` 候选）
- ⭐ **探索档的价值**：只多一次冷测（≈25s ✓），就把"**未测边界**"变成**定量边界**（~2600 条 ≈ 一帧 ✓）—— 便宜且有用 ✓
- ⭐ **冷噪实证**：`n200 cold [5, 5.6, 6.6]` ⇒ 极差 **32%** ✓ ⇒ **"单样本不可用"的活例证** ✓（首轮 cold n=1 也出现过 n500 7.9 < n200 9.9 的倒挂 ✓）
- ⚠ **相对导入别手写层级** ✗：`../../tools/cdp.mjs` 应为 `../tools/cdp.mjs`（**同族第 2 次** ✗）⇒ 一劳永逸写法：
  `const cdp = await import(new URL('../tools/cdp.mjs', import.meta.url).href)` ✓（放到哪一层都不会错 ✓）；
  写前 `Test-Path`/字面串存在**断言**，不成立就**中止不写盘** ✓
- ⚠ **读含中文的 JSON/日志必须显式 UTF-8** ✗（Lead 本轮亲踩：`Get-Content -Raw | ConvertFrom-Json` 把 `notes` 按 ANSI 读 ⇒ 解析失败 ✗）
  ⇒ 用 `[IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` ✓（或 node `readFileSync(p,'utf8')` ✓）
