# 批次 3 · Q2 报告：`modu-recent` 的双反斜杠是**当前代码**写的吗？

日期：2026-09-23 ｜ 执行：modu-shell ｜ 关联：批次 3-4（隔离/取证工具族）、A6 报告

## 结论（一句话）

**当前代码不写双反斜杠** —— `modu-recent` 只有一个写入点（`main.ts:230 pushRecent(path)`），
它**逐字存储调用方给的串**，且调用方拿到的都是 Rust 侧对话框/受信登记/已存值 ⇒ **没有任何一处会产生 `\\` 加倍**。
隔离 profile 里那两条双反斜杠条目是**旧版本遗留**，并会**原样回灌**（菜单点击 → `loadRecent()` 旧值 → 原样存回），
表现为"同一文件两条"，但**不是当前代码造成的**。

## 一、写侧（代码，权威）

| 项 | 事实 |
|---|---|
| 唯一写入点 | `modu/src/app/recent.ts:52 pushRecent()`；**全仓唯一调用点** `modu/src/main.ts:230`（`git grep -n pushRecent -- '*.ts'` 权威复核） |
| 写入内容 | `const list = [path, ...loadRecent().filter((item) => item !== path)].slice(0, 10); localStorage.setItem(KEY, JSON.stringify(list))` ⇒ **逐字存 path，无转义/无规范化** |
| `path` 来源 | `openPath(tabs, path)`（`main.ts:226`）的三类调用方：**① 最近菜单** `setupRecentMenu((path) => openPath(...))`（`:755`，path 来自 `loadRecent()` = 已存值）**② 打开对话框** `pick_markdown_files` 的 IPC 返回（Rust 侧原生路径）**③ 拖放/命令行**（同一受信清单） |
| 结论 | 代码路径上**不存在**"把单反斜杠变双反斜杠"的环节 ⇒ **当前代码不写双反斜杠** ✓ |

补充（本轮方法学教训）：我第一次查调用点时用了 `Select-String -Path src\**\*.ts` ⇒ **漏掉了 `main.ts:230`** ✗，
差点得出"`pushRecent` 是死代码"的错误结论；改用 **`git grep`** 才看到 ✓（**第 7 例**"看不见 ≠ 不存在"）。
