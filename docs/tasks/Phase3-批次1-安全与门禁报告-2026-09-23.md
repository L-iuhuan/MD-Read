## 1. 任务 1（L）· R-01 路径白名单 + scope 收紧

### 1.1 信任模型（照 D-09 / D-10 落地，未自创）

`docs/tasks/Phase2-前-决策登记-2026-09-23.md` 的 D-10 裁决：**把"用户曾经打开过的路径"持久化为受信集合**；
最近文件直接打开；**仅当缺失/不可读/不在受信集时才提示**。据此：

- 受信集合 = 用户主动打开过的**文件**（canonical 形态）+ 受信**目录**（D-11 文件夹工作区/将来另存的落点）。
- **注册入口只有四条，全部在 Rust 侧、渲染层伪造不了**：
  1. **Rust 侧文件对话框**：新命令 `pick_markdown_files`（对话框搬进 Rust —— JS 的 `plugin-dialog` 只把结果给渲染层，Rust 无法判断"这路径是不是用户选的"）；
  2. **OS 拖放**：`WindowEvent::DragDrop(DragDropEvent::Drop)` → Rust 侧登记；
  3. **命令行 / 双击文件关联**：`setup` 里 argv + 单实例转发的 argv（`single.rs` 回调）里登记；
  4. **持久化清单**：`%APPDATA%\com.modu.reader\trusted-paths.json`（重启后仍受信 ⇒ 最近文件零打扰重开）。
- ⚠️ **刻意不提供** `allow_path` 这类渲染层可调命令：否则攻陷页面先 `allow_path(任意路径)` 再 `read_file` 就自证授权了（设计稿 §7.2 的反例）；`trust_dir` 同理**不是命令**，只作为库函数留给将来接线。

### 1.2 改了什么（显式路径）

- 新增 `modu/src-tauri/src/trust.rs`（受信集合 + 纯策略 + 持久化）、`trust_tests.rs`（10 组边界用例）。
- `modu/src-tauri/src/fs.rs`：`read_file` / `save_file` 命令接 `State<TrustedPaths>` 并先过受信校验；抽出 `read_file_checked` / `save_file_checked` / `read_file_at` / `save_file_at` 供直测；新增 `pick_markdown_files` 命令；IO 错误改成中文原因（**不再把 `os error 2` 塞进 UI**）；新增 `fs_trust_tests.rs`。
- `modu/src-tauri/src/lib.rs`：`pub mod trust`；`.manage(fs::load_trusted_store(app.handle()))`；argv 登记；`.on_window_event` 处理拖放登记；注册 `pick_markdown_files`。

### 1.3 防御要点（为什么这样能真的收紧）

- **规范化后比较**：`fs::canonicalize` 收敛 `..`、相对路径、8.3 短名、符号链接/junction、盘符大小写；
  集合键统一**小写**（Windows 大小写不敏感），避免"注册 A、查询 a 都通过"的错配。
- **默认拒绝**：`classify_name`（绝对路径 + `.md/.markdown/.mdx`）→ `canonicalize`（含存在性）→ 是普通文件 → 才可能入库；查询侧不在集合内一律 `Err`。
- **读写都用 canonical 落盘**（避免 TOCTOU 二次解析）。
- **中文文案**（面向使用者、不露技术黑话）：`无法读取文件：<路径>（该文件不在本次已打开的清单中，请用「打开文件」重新选择）` / `（文件不存在或已被移动）` / `（路径必须是完整路径）` / `（只支持 Markdown 文件：.md / .markdown / .mdx）` / `（不是文件）`。
- 持久化清单**损坏/版本不符 → 空集合启动**（安全侧默认拒绝，绝不放行）。

### 1.4 Rust 单测（`cargo test` EXIT=0：45 lib + 4 roundtrip）

覆盖设计稿 §6.1 的边界（`trust_tests.rs`）：相对路径 / `..` 穿越 / 同目录不同文件 / 大小写别名 /
中文与空格路径 / UNC（**只在纯策略层判形状**，不触发网络 canonicalize）/ 目录 / 缺失文件 /
非 .md / 白名单外写入 / `forget` 后失效 / 持久化往返 / 清单损坏与版本不符降级 / 受信目录按**路径分量**命中
（`C:\books` 不得命中 `C:\books-elsewhere`）/ 符号链接（**建不出来就打印跳过，不假装通过**）。
`fs_trust_tests.rs`：**被拒的写入磁盘一个字节都不动**（哨兵比对）、被拒读的中文文案不含英文 OS 错误、

### 1.7 判断与遗留（需要你知道的取舍）

1. **持久化键是 `\\?\` 扩展长度形态**（Windows `canonicalize` 的产物）：注册与查询两侧都过同一个
   `canonicalize`，因此自洽（①⑨ 实测通过）；清单文件可读、可手删。若你希望清单里是人类可读的
   `D:\...` 形态，我可以加一层"去 `\\?\` 前缀"的展示/解析（**当前未做**，因为那会引入第二种形态、
   反而增加不一致风险）。
2. **关窗落盘遇未受信路径仍会阻止关窗**（`saveDirtyTabs` 语义未改）：我选择**不**静默跳过 ——
   "未保存的编辑被丢掉"比"关不上窗"更糟；且 UI 上开出来的标签必然已受信，这条实际不可达。
3. **PDF 另存（`pick_save_path`）未纳入受信集合**：它走的是独立命令，不经 `save_file`；
   "md 另存为"今天不存在，受信目录机制已就位（`trust_dir` + 父目录判定，含单测），等将来接线。
   **这是一处需要你确认的取舍**：要不要把"用户选过的 PDF 目录"也登记为受信目录？我倾向**不**（避免用一次导出扩大读写范围）。
4. **`opener` 只收窄了未用项**：`opener:default` 里的 `mailto:`/`tel:` 本就在 `allow-default-urls` 的

## 2. 任务 2（S）· 敏感门禁真能一键跑

### 2.1 原来的三个坑（对账属实，已实测复现）

1. 脚本注释写 `pwsh -File ...`，而**本机没有 `pwsh`**（只有 Windows PowerShell 5.1）；
2. 默认执行策略下 `powershell.exe -File scripts\check-sensitive.ps1` → **不是数字签名**、exit 1（实测）；
3. 仓库无 CI ⇒ 谁也跑不了。

### 2.2 做了什么

- **注释改成实测可跑的调用方式**，并写清"为什么必须是这个写法"（`-ExecutionPolicy Bypass`：RemoteSigned 拒签；
  用 `powershell.exe` 而不是 `pwsh`：本机没有 pwsh），退出码语义也写明（0/1/其它）。
- **新增薄包装 `scripts/check-sensitive.cmd`**（纯 ASCII 注释 —— cmd 按 OEM 码页读文件，中文注释会被打碎并当命令执行，本轮真踩到）：
  固定 `-NoProfile -ExecutionPolicy Bypass`，`exit /b %ERRORLEVEL%` 原样透传。无网络、无额外依赖。
- **把 `$LASTEXITCODE` 的坑写进脚本头**：`cargo test 2>&1 | Select-Object -Last N` 会因 PowerShell 把原生命令
  stderr 当 `NativeCommandError` 而**假报 exit 1**；判退出码永远显式读 `$LASTEXITCODE`。
- **脚本文件重新加回 UTF-8 BOM**（PS 5.1 读无 BOM 的 .ps1 会按 ANSI 解，中文全坏 —— 本轮改注释时真的把文件写坏了、
  已修回并核对 BOM = `239,187,191`）。

### 2.3 实测（都在本机跑过，退出码是 `$LASTEXITCODE`）

| 场景 | 命令 | 退出码 / 输出 |
|---|---|---|
| A 不按文档（缺 Bypass） | `powershell.exe -NoProfile -File scripts\check-sensitive.ps1` | **1** + `check-sensitive.ps1 is not digitally signed…` ⇒ 证实"照旧文档跑不了" |
| B 文档里的方式 | `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\check-sensitive.ps1` | **0** + `✅ 敏感信息门禁通过（扫描 135 个文件，模式 17 条）` |

### 5.5 `allow_asset_paths` 上界核实（Lead 追问；实测/推断分开）

| 问题 | 回答 |
|---|---|
| 1. 有没有上界？ | **只有"绝对路径 + 图片扩展名（9 种）+ 存在 + 是普通文件"**；**没有受信集合/目录约束**。实测：位于任何受信文档目录**之外**的图片 → 授权前 `error`、`allow_asset_paths` 后 **`loaded`** ⇒ 渲染层可授权**任意本地图片**。非图片/相对/缺失路径被**静默跳过**（仍返回 `Ok`，P0-3 既有"缺图不连坐"语义）。 |
| 2. 能否收紧到受信集合？ | **可以**。规则建议：图片必须落在「含已受信文档的目录」之下或「受信目录」之下（`trust` 侧加 `allows_image(path)` 纯函数 + 单测）。**风险**：markdown 用绝对路径引用文档目录之外的图片会被一并拒掉 —— 收紧前需先取语料核实这种写法是否存在。 |
| 3. 结论 | **已写进 `lib.rs` 的 `allow_asset_paths` 注释**（入库，含实测数字与"待批次 2 裁决、勿擅自改"）。暴露面评估（CSP `connect-src 'self' ipc:`、无 canvas 读回）标注为**推断**；"能显示任意本地图片 + onload 计时当文件探针"是**实测可达的越权**。**本轮按 Lead 指示不动代码**，收紧留给批次 2 裁决。 |
