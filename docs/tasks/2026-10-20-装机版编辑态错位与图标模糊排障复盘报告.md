# 装机版编辑态错位与图标模糊排障复盘报告（0.2.8）

> 日期：2026-10-20 · 范围：`modu/` 前端编辑态样式链路、Windows 图标资产 · 版本：0.2.8
> 结论一句话：**编辑态"行号在上、内容在下、左侧没行号"不是 CM6 测量/缩放 bug，而是 Tauri 生产 CSP 把 CM6 运行时注入的样式整段拦掉**；图标模糊是**尺寸档缺失 + 小尺寸由细节稿缩小**两因叠加。两项均已修并在**生产构建真机**验证。

---

## 一、用户反馈

1. 编辑态下「行号在上、右侧什么也没有、内容在下方、左侧没有行号」，疑似缩放问题；本地安装的版本仍未修好。
2. 图标分辨率低、看起来糊。

---

## 二、问题一：编辑态行号/内容错位（真根因：生产 CSP 拦截运行时样式）

### 2.1 现象与取证（实测，非推断）

对**已安装的 0.2.7 生产 exe** 用 CDP 取证（隔离 profile + `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=…`）：

- CM6 的 DOM 正常存在（`.cm-editor`、`.cm-gutters`、`.cm-content`、行号内容都在），但几何全为默认块布局：
  `.cm-scroller` 的 `display` 计算值是 `block`（应为 `flex`），`.cm-content` 掉到行号列下方。
- 页面里 **DOM 有 CM6 注入的 `<style>`（16KB，含 baseTheme），但 `styleTag.sheet === null`**，
  `document.styleSheets` 里没有它 ⇒ 样式表根本没被创建。
- 运行时注入一个测试 `<style>`：同样 `sheet === null`，且触发 `securitypolicyviolation`，`effectiveDirective = style-src-elem`。
- 生产页面响应头 `style-src` 含 `'nonce-…'` 与 `'sha256-…'`。按 CSP3：指令中出现 nonce/hash 后
  `'unsafe-inline'` **被忽略** ⇒ 运行时创建、无 nonce/hash 的 `<style>` 一律被拦。
- `pnpm tauri dev` 走 Vite 页面、没有这层生产 CSP ⇒ **历轮 dev/隔离 dev 验收全绿，装机版一直是坏的**。
  0.2.4~0.2.7 的"行号错位"修复均未触达真根因。

### 2.2 修复

`modu/src-tauri/tauri.conf.json` → `app.security`：

```json
"dangerousDisableAssetCspModification": ["style-src"]
```

- 只关闭 Tauri 对 `style-src` 的 nonce/hash 注入，保留 `style-src 'self' 'unsafe-inline'`（本来就是该 CSP 的意图）；
- `script-src` **仍由 Tauri 收紧**（未整体设 `true`、未放开脚本），安全面不扩大；
- 影响面说明：CSP 的 inline-style 允许范围没有比配置原意更宽；HTML 注入面仍由 `html:true` 禁用 + DOMPurify 把守。

### 2.3 验证（生产构建真机，数值判据）

探针：`modu/tests/tools/probe-align.mjs`（新增入库；`--expect-version 0.2.8` 同时防"测到旧 exe"）。

| 判据 | 结果 |
|---|---|
| 生产响应头 `style-src` | `style-src 'self' 'unsafe-inline'`，无 nonce/hash ✓ |
| CM6 注入 style 的 sheet | `sheetNull=false`，`.cm-scroller` display=flex ✓ |
| 编辑态逐行对齐（可见行号 vs `.cm-line` 的 top 差） | 100%：`dy=0px`（>1px 计 0 行）✓ |
| 缩放五档 90/100/110/125/150 | 每档逐行 `dy=0px`；正文/行号字号同源（16→14.4/16/17.6/20/24px）✓ |
| 长文滚动 4200px 后复测 | `dy=0px` ✓ |
| 阅读→编辑→阅读→编辑 二次进出 | `dy=0px` ✓ |
| `.cm-editor` 上 CSS zoom | 无（`zoom=1`，`--paper-zoom` 变量语义缩放）✓ |
| 行号位置 | 行号右缘贴正文内容盒左缘（正文自身 6px 内边距形成视觉间距），不重叠 ✓ |

本地证据（`.verify/` 已 gitignore，不入库）：`.verify/align/run-028/report.json` 与同目录各档截图；
0.2.7 坏态对照在 `.verify/align/run-1792478591259/`。

## 三、问题二：图标模糊

### 3.1 根因（实测）

- 旧 `icon.ico` 只有 7 档（16/24/32/48/64/128/256）、`file-icon.ico` 只有 5 档；**缺 20/40/96**。
  本机 UI 缩放下 125% 时，标题栏 16 逻辑 → 20 物理、任务栏 32 逻辑 → 40 物理，缺失档位只能由邻近尺寸缩放 ⇒ 糊。
- 所有小尺寸都由细节稿 `f1-app.svg`（渐变纸页/折角/柔和投影）直接缩小 ⇒ 16~48px 发灰、发糊。

### 3.2 修复

- 两个 ICO 统一 10 档：**16/20/24/32/40/48/64/96/128/256**；
  ≤128 为 32bpp BMP 条目（BITMAPINFOHEADER + 底向上 BGRA + AND mask），256 为 PNG 条目。
- **≤48px 使用像素级小尺寸变体**（`icons-src/f1-app-small.svg` / `f1-file-small.svg`：平涂、粗框、大 M），
  >48px 用细节版；每档都按目标像素直接光栅化（不做缩放）。
- 同步重生成 tauri bundle 的 15 个 PNG（主 PNG + Square*/StoreLogo，文件名/尺寸不变）。
- 可复现生成器入库：`modu/tests/tools/build-icons.py`（cairosvg + Pillow，无新增 npm 依赖）；
  口径与风险见 `modu/src-tauri/icons-src/README.md`。

### 3.3 验证

- ICO 条目表逐项解析；PIL 打开 10/10 帧；每帧与源 SVG 复渲染逐字节/逐像素比对（≤128 全等，256 仅 RGB Δ≤2）；
- 圆角外 alpha=0、无黑角白边；16px 结构可辨性判据 PASS；Windows `LoadImageW` 对两个 ICO × 10 尺寸 20/20 加载成功；
- 生产 exe 内嵌图标逐字节核对：`icon.ico` 的 **10/10 条条目 payload 均原样出现在构建出的 exe 中**；
- A/B 证据（`.verify/icon-final/`，gitignored）：`contact-sheet.png`、`ab/before-after.png`、`ab/ab-40-48.png`。

### 3.4 已知风险 / 说明

- **Windows 图标缓存**：升级安装后 Explorer/任务栏可能短时显示旧图标；刷新方法见 §六。
- 48↔64 之间是「小尺寸粗体微变体 → 细节稿」的形态切换点（为兼顾 16~48 可辨性与大尺寸质感而刻意为之）；
  若希望更统一的观感，可只改 `build-icons.py` 的尺寸→变体分界后重跑。
- 256 条目 RGB 量化到步长 5（最大 Δ2/255，肉眼无差）以守住 ICO 体积；要完全无损可改生成器参数。
