## 二、逐条定性

### 1. `mermaid`（**已消除** ✓）
- **成因（实测）**：`view.ts:7 import { observeMermaid } from './mermaid'` **静态**导入 ⇒ `mermaid.ts` **本来就在首屏 chunk 里**；
  而 `print-ready.ts:110` 又写 `await import('./mermaid')` ⇒ **拆不出任何东西**（rolldown 告警完全正确）
- **处置**：改成 **静态导入**（`import { renderMermaidEl } from './mermaid'` + 直接调用）
  ⇒ **运行时零差异**（模块早已加载 ✓）、函数仍 `async` ✓、`PrintReadyOptions.renderPending` **注入缝不动** ✓
- **实测效果**：`INEFFECTIVE_DYNAMIC_IMPORT` **4 → 3** ✓；初始 chunk **828.92 → 828.68 kB**（可忽略）✓；`pnpm build` EXIT 0 ✓
- 顺带修准 2 处注释（"默认动态加载…" → "静态导入 + 为什么"）✓

### 2–4. `@codemirror/lang-{css,javascript,html}`（**不消除，理由如下** ✗）
- **成因（实测传递链）**：`editor.ts:11` **静态**导入 `@codemirror/lang-markdown@6.5.2`，
  而实测其 `dependencies` 含 **`@codemirror/lang-html@6.4.12`**，后者 `dependencies` 又含
  **`@codemirror/lang-css`** + **`@codemirror/lang-javascript`**
  （HTML 内嵌 `<style>`/`<script>` ⇒ 这是上游的设计）
  ⇒ 三者**本就在首屏 chunk 里**；`editor.ts:22/24/32/34` 的懒加载语言表**拆不动**（告警正确）
- **要真消除**，只能把**编辑器的核心 markdown 模式**也改成懒加载 ✗ ⇒ 那是**行为变更**（首次进入编辑态的加载时延 +
  一整套异步化风险），**为一条纯提示性告警不值得** ✗
- **无害性（推断，标清）**：这三个包是"**编辑态**才会用到"的语法高亮支持，体积固定；
  懒加载**从未生效**过 ⇒ 现状与"改了名字的现状"完全一致 ⇒ **无功能损失、无体积收益可失**

## 三、「chunk > 500 kB」告警：**接受，不拆**（合格结论，附理由）

| 理由 | 说明 |
|---|---|
| ① 本地加载，非网络传输 | Tauri 走本地协议读 `dist/` ⇒ 828 kB **不是下载成本**，主要是解析成本；打开速度**已有实测预算表**（AGENTS.md：冷开 ≤10 页 38ms / ≤200 页 165ms）**均达标** |
| ② 红线是**另一个独立指标** | 8MB 是 **MSI 安装包**上限；MSI **≤** web 产物 + Rust 二进制，本轮已实测（见 §四），不因 chunk 拆分而改善（拆 chunk 不改总量） |
| ③ 拆分有真实风险 | 动 `codeSplitting` = 改首屏加载图 ⇒ 需重跑真机打开性能 + PDF 导出 + MSI ⇒ 收益（去掉一行告警）与风险**不成比例** |
| ④ **不改 `chunkSizeWarningLimit`** | 按 Lead 口径：**不许为过 lint/告警放宽配置**；调阈值只会把告警藏起来 ✗ ⇒ 不做 |
