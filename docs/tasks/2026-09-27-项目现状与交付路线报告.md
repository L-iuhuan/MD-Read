## 4. ⚠ 我知道但**还没做**的（逐条 + 原因，不藏 ✗）

### 4.1 main 的 CI 是红的 ✗（**最高优先**）
- 事实：该仓库 CI **已跑过 69 次**；最近几次都在 main 上，
  **敏感门禁 ✓ success · 前端门禁 ✓ success · `Rust 单测（cargo test）` ✗ failure**。
- 已做的决定性实验（**否证**）：本机**干净 clone**（clone 到工作区外，避开那个 `Low` 完整性标签 ✗）
  **同时跑了 `main`(`01befba`) 与本分支** ⇒ `install 0 · build 0 · cargo test 0`（59+4 / 79+4）✓
  ⇒ ⭐ **"缺文件 / 未入库 / 干净 clone 建不出来"这一整类被排除** ✓（含曾担心的 `../dist` ✓ 已由 CI 的前端产物步覆盖 ✓）
- ⇒ 候选**只剩 runner 侧**：镜像差异（WebView2 / MSVC / Node 22）·
  `Swatinem/rust-cache@v2` 的**陈旧缓存**（经典成因）· `actions/*` 行为
- ⚠ **不按猜测改代码** ✓ —— 需要①失败日志（**下载需仓库管理员** ✗）或②在 runner 上真跑一次 ✓

  ⇒ 本分支加的 `workflow_dispatch` **在 main 上还没有** ⇒ **按钮现在不会出现** ✗
  ⇒ 想立刻让 CI 真跑，可行的办法是：**把本分支合进 main 后 push** ✓（push 到 main 才会触发 ✓）
