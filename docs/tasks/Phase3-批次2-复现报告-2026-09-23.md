### 关于 P1-3 的**推断原因**：那是**设计上的代价，不是缺陷**（请勿再当 bug 优化）

`guardJustify` 用 `el.clientWidth` + `naturalLineWidths()` 判定；**读 `clientWidth` 会强制该子树排版**，
所以即使块在视口外、`content-visibility: auto` 尚未渲染，也能拿到真实宽度 ⇒ 守卫不盲。
代价是：这**正是**性能 profile 里 `getBoundingClientRect` 排第一（9.1ms）的那类"按需排版"成本的来源。
**它是"守卫要判得准"换来的已知成本**，不是漏判。⇒ 台账与批次 2 清单请按"⚰️不成立 + 设计代价"处理，
**不要**再去"优化"它（除非整体改成真虚拟化 —— 那是另一个议题）。

## 1. P1-1 `$$…$$` 无数学保护 —— ❌ 仍是缺陷

**复现步骤**：`.verify/phase3b/corpus/repro.md`（第一轮版本）里放两个 `$$` 块（第二个内部含一行**孤立的 `=`**），
启动应用（argv 传参受信）→ 探针 `probe-repro.mjs` 读 `#doc`。

**实测（`out-repro.json` → `p1_1`）**：

| 观测项 | 实测值 | 说明 |
|---|---|---|
| `katexCount` / `mathBlockCount` | **0 / 0** | 两个 `$$` 块**一个都没渲染成公式** |
| `dollarLeftovers` | **6** | `$$` 以字面文本留在正文里 |
| 第一个块的段落文本 | `"$$\na b c\n$$"` | 源文是 `a *b* c` ⇒ `*b*` 被 emphasis 吃掉（`textContent` 里只剩 `a b c`），**即清单说的 `<p>$$a <em>b</em> c$$</p>`** |
| `emInsideMath` | 0 | 因为压根没有 `.katex`（不是"em 在 katex 内"） |
| **headings** | `[{H1,"P1-1 / P1-3 / P2Q-34 复现语料"}, **{H1,"$$\nE = m c^2"}**, {H2,…},{H2,…}]` | ⚠️ **第二个 `$$` 块前两行被渲染成 `<h1>`** ⇒ **mdput 的"孤立 `=` → setext 标题"线索确认**（`=` 独立成行 → 上一段成了 H1） |
| `isolatedEqualsInHeading` | 1 | 同一个 H1 的文本里就含那个 `=` 的产物 |

**typographer（`typographer: true`，`src/render/markdown.ts:179`）实测**：源文
`他说“这样”很好 -- 真的很好…… 还有 a--b。` → 渲染后
`他说“这样”很好 – 真的很好…… 还有 a–b。`
⇒ **`--` → `–`、`...` → `…`、直引号 → 弯引号 全部发生（实测）**。`mathprotect.ts:19` 的设计意图是
"md 转义 / linkify / typographer / emoji 均不会改写"（**仅对已被 extractMath 收走的片段成立**）；
而 `$$` 多行块**没有**被收走，所以内部文本照样被 typographer/emphasis 改写。

**推断（未做代码级归因实验）**：`extractMath` 的守卫很可能只认**单行** `$$…$$`（或对内部含 `\text{}`、
空行、多行的形态处理不同），于是多行显示公式整块漏出。⇒ 修 P1-1 时应先加一条"多行 `$$` 也必须被收走"的用例。

## 3. P1-3 离屏 justify 守卫漏判 —— ✅ 已不成立（复现失败）

**复现设计**：`repro.md`（高文档版）= 首屏内控制组（`yyyy`，多行 + 超长 token）+ 50 段填充 + **首屏之外**同构组（`zzzz`）；
两者形状完全相同（207 字符、4 行）。判据：`data-justify="off"` 是否存在。

**实测（`out-repro2.json` → `p1_3_mount`）**：
```
contentVisibility(仅 #doc 自身计算值) = visible   docChildren = 7
control  (yyyy, inViewport=true )  dataJustify="off"  clientWidth=736  lines=4
offscreen(zzzz, inViewport=false)  dataJustify="off"  clientWidth=736  lines=4   ← 离屏组也已被标记
```

`p1_3_forced.reranGuard=false`（守卫没有在滚动时重跑——**也不需要**，因为挂载时已经判对）。

**结论（实测）**：清单说的"离屏 → 守卫漏判、进视口后仍无"**没有复现**。原因（**推断**）：`guardJustify` 读的是
`el.clientWidth` 与 `naturalLineWidths()`，**读 `clientWidth` 会按需为该子树排版**，所以即便块在视口外
（`content-visibility: auto` 未渲染），也能拿到真实宽度 736 并正确判定。⇒ 这条**建议从批次 2 清单里划掉**

## 5. P2Q-34 复制钮随 `pre` 横移 —— ❌ 仍是缺陷

**实测（`out-repro.json` → `p2q34`）**：
```
pre: overflowX=auto, position=relative, clientWidth=734, scrollWidth=990（确实可横滚）
.code-copy: position=absolute, right=8px, top 区（按钮由 codecopy.ts 挂在 pre 内）
scrollLeft 0   → pre.left=573, 按钮 left=1276
scrollLeft 256 → pre.left=573, 按钮 left=1020   ⇒ 按钮位移 −256px（= scrollLeft 增量）
buttonMoved = true
```
**根因（实测 + 代码）**：按钮是 `pre` 的**绝对定位子元素**，而 `pre` 是横向滚动容器 —— 绝对定位的包含块是
滚动容器的**内容盒**，于是内容和按钮一起被滚走。⇒ 需要把按钮挪到不随内容滚动的层（外层 wrapper 定位，或
`position: sticky; left/right`）。
